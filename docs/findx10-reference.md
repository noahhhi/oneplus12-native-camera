## 三项后续能力

1. **4K Live HDR Photo**：旧相机已有高像素 4K Live 和 HDR 时选择 HEVC Main10 的分支。新相机增加高像素 4K Live 动态预览选择及会话切换处理；参考配置还启用了 P010 打包、FRC 等路径。不能把编码器标志或预览尺寸当作最终动态片段已具备真实 4K HDR 的证据，封面与片段需分别验证。
2. **大师 Live Photo**：两份原始配置中的大师 Live 支持标志都已开启；单独修改该标志不是解锁方案。还需检查实际模式、曝光、格式、界面入口和会话组合的限制。
3. **Xpan Ultra HDR**：参考实现不止一个 `xpan` 滤镜流程，还包含 `xpan_parallel` 的 RAW/HybridRAW、HDR 变换、mask refine 与 DCG 融合等能力及决策分支。它和一加基线的原生算法配置不同，不能直接复制 MediaTek 的算法图或库，也不能仅凭这些配置宣称一加已能生成原厂 HDR 增益图。

另有明确 JNI 变化：`HardwareBufferUtils.nativeCopy` 增加一个 boolean 参数；反汇编显示它控制 U/V 两个平面中较低地址的选择，并非 HDR 或 4K 开关。Java 声明和 native 实现需要配套。

## 与录像闪退的关系

对照可读的完整方法，参考 SDK 的停止录制、EOS、高通录像状态和动态范围设置未发现可直接复用的修复；关闭设备仅多出一处自动闪光状态复位。新 MMF HDR 请求映射属于不同路径，也不能替代当前 LocalHDR/SSTAB 故障证据。

现有录像补丁逐帧判断坐标条件，跨阈值可能使整幅坐标补偿切换。这一不连续机制已可由代码确认，但尚未证明它引发闪退。扩展对象生命周期、额外线程栈占用、厂商录像链与资源问题同样需要崩溃现场，不能先凭猜测改常量或更换库。

下一次真机研究先保存相关 crash log/tombstone，确认故障进程、信号和 PC，再分开测试静止长录、轻运动、启停及切镜头，使用 SDR、30fps 与仅撤销录像模块的对照。照片修复与录像回退继续分开处理。
